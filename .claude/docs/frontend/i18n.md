# frontend i18n — language choice and message catalog

## Purpose

The SPA has one UI language at a time: `en` (default), `pt-BR` or `ru`. `LanguageProvider` holds it
in React context and persists it under the `localStorage` key `dmitri-language`; an unknown stored
value reads as `en`. Components call `useI18n()` to get `{ language, t }`. `t(key, variables)` looks
up a typed `MessageKey` in the catalog in `messages.ts`; a catalog value is a string or a function of
the variables. There is no i18n library and no lazy loading — all three catalogs ship in the bundle.

The same `language` value is the AI output language: the scan overview, scan and context chat, and
the report download pass it to the backend (see [scan-ai](./scan-ai.md), [context-ai](./context-ai.md)).

## How it connects

- Mounted in the root provider nest inside `SessionProvider` ([app](./app.md)).
- Chosen from the `TopBar` preferences menu ([screens](./screens.md)).
- Language-keyed queries: `queryKeys.scans.analysis(scanId, language)` ([api](./api.md)).

## Notes / gotchas

- **Migration is partial.** About 30 components use `useI18n`, but some copy is still hard-coded:
  `HomeAIOverview` keeps Portuguese text, and a few `aria-label`s (`Idioma`, `Abrir menu`,
  `Navegação principal`) are Portuguese in every language. `lib/copy.ts` constants other than
  `UI_COPY` are English only.
- **Two tables, one language.** `UI_COPY` in `lib/copy.ts` is separate from `messages.ts`; its
  comment says page messages move to the catalog "journey by journey".
- `LanguageProvider.test.tsx` covers the English default, the three options, and persistence.
