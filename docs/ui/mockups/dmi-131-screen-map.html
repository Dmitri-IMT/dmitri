Dmitri Screen Map

Every screen in the web app, with the one thing it exists to show, the one action it offers, and where findings appear grouped by how soon they need work. Comment on any card: this map is the input to the per-screen issues, and to the restyle that follows.

Bound by decisions already made — findings are grouped into cards, never chipped per row; copy never says the network is safe; one primary action per screen, in the page header; top bar navigation; light theme; desktop.

Cut list

Things the screens render today that this map drops. Veto any of them.

Severity chips on rows
The group heading already says how soon; a coloured dot asks the reader to learn a code.
"Highest severity" column
Same reason, in a table. A count of Fix now items says more in plain words.
"Dmitri scans your network…" on Scans, Devices and blank Home
The reader is already inside the product. Three copies of the pitch.
The engraving ornament on Home
It belongs to the retired paper-and-serif look, not the new one.
Buttons inside content cards
One primary action per screen, always in the header, so it is in the same place everywhere.
Raw addresses and jargon as row titles
A device is named by its name; the address becomes secondary text.
Scan mode shown per row
The product only ever runs one mode. Showing it implies a choice that does not exist.

Decisions this map asks for

Six answers unblock the per-screen issues.

  1. Approve or reject the three renames: Hosts → Devices, Agents → Scanner, Users → People.
  2. Decide whether Start scan appears on Home and Scans, or only on Scanner.
  3. Confirm Good to know is hidden on Home and shown only on the detail screens.
  4. Choose the plain words for the two access levels, replacing Admin and Viewer.
  5. Confirm the severity chip and the highest-severity column are cut from every table.
  6. Decide what a device that has stopped answering is called, and whether it stays in the list.
