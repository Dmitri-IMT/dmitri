## HTTP contract

All paths below use `/api/v1`. Member reads are scoped to caller org; another org receives 404. Mutation requires existing require_admin plus a live user/admin row check in the same admission transaction. Device reports use require_agent, fresh Ed25519 timestamp/nonce/body hash, and explicit path/operation ownership checks. A browser never receives device credentials.

| Method / path | Proposed result and effects |
|---|---|
| GET `/agents/{agent_id}` (existing, extended) | Last `observed_version`, `observed_package_version`, `version_observed_at`, `active_update_id`; nullable until observed; retain while offline. Freshness and current capability are separate from historical version. |
| GET `/agents/{agent_id}/updates/availability` (N) | `availability: available/up_to_date/unknown/unavailable`, nullable approved release, `catalogue_checked_at`, `catalogue_valid_until`, `device_readiness: ready/offline/revoked/bootstrap_required/busy/unknown`. Pure DB/current-registry read; no refresh, claim or installation. |
| GET `/agents/{agent_id}/updates` (N) | Cursor/limit history of this device's operations, newest first. |
| GET `/agent-updates/{update_id}` (N) | Operation with previous/target/locally observed versions, phase, local outcome, remote confirmation/contact timestamps, closed error code and actor/time audit. |
| POST `/agents/{agent_id}/updates` (N) | Required UUID Idempotency-Key; body only `{release_id, expected_observed_version}`. 202 plus operation/Location for new intent; same key/body → 200 same operation without redelivery; different body → 409. Commit intent before one send on captured live session. |
| GET `/agents/{agent_id}/update-protocol` (N, signed device read) | Supported update protocol versions and explicit supported capabilities, including `scan_finalization_v1`; new client probes before extended hello. 404/unsupported → legacy hello and legacy scan lifecycle when no protocol-1 checkpoint is pending. No install side effect; support does not imply device installation readiness. |
| POST `/agent-updates/{update_id}/claim` (N, signed device) | `{session_id, release_id, target_package_version, sha256}`. After local exclusive lock and durable intent, admit once against current unexpired requested operation/session; commit preparing and return bounded authorization receipt. Same claim returns same receipt, never extends its deadline. |
| POST `/agent-updates/{update_id}/events` (N, signed device) | Durable `{sequence, phase, local_outcome, observed_version, package_version, invocation_id, session_id, occurred_at, error_code}`; nullable evidence where absent. 200 with committed `ack_sequence`; retry same event with new auth nonce. No arbitrary logs/config blobs. |

Release response schema binds release_id, package=`hardware-agent`, upstream/package versions, architecture/suite, hash/size, required protocol/updater, published_at and bounded plain-text release notes. No download URL comes from a browser. Backend resolves the ID from the verified catalogue; updater independently verifies the same mapping through its fixed repository. Availability describes catalogue evidence, not proof that APT installation will work.

Catalogue missing/expired/unverifiable means unavailable, not up_to_date. Unknown installed version means unknown and prevents admission. All GETs remain read-only; the background worker handles catalogue refresh and request expiry. A refresh button may refetch GET but cannot wake a device or update package metadata. UI uses the existing API client and TanStack Query, typed from OpenAPI; it polls active operations and invalidates device/availability/history after mutations. Viewer controls are absent; request failures use localized toasts, while phase/local-outcome facts remain ordinary status data. No percentages are invented.

## WS contract, compatibility and reconciliation

Keep the signed WSS upgrade `/agents/{agent_id}/commands`, all scan command/cancel/status/progress shapes, subnet checks and scan ingestion. New backend accepts legacy hello unchanged. Extended hello adds optional `capabilities`, `updater_version`, `package_version`, `os_suite`, `architecture`, and `update_context` containing operation/invocation IDs when relevant. On every connection the new agent probes backend support before extended hello. Tasks 7/8 negotiate `scan_finalization_v1` independently of the supervisor's installation readiness; a pending checkpoint must not suppress that capability. Installation fields/context come from local observed state, and `agent_update_v1` is announced only in Task 12 after its prerequisites pass. Missing `agent_update_v1` is bootstrap_required for updates, regardless of numeric agent version or finalization support.

For negotiated `scan_finalization_v1` or `agent_update_v1`, backend replies `type=update_session` with a fresh session UUID tied to this socket. This frame provides session correlation only; it grants no installation authority. Backend → agent `type=agent_update` requires `agent_update_v1` and carries only update_id, session_id, release_id, target_package_version, sha256 and expires_at. It contains no scan_id, mode, subnet, URL, shell or argv. Agent hands it to the root-only companion socket; the companion durably validates/claims it. Task 12 advertises both capabilities when installation is ready. All extra fields and unsupported frame types fail schema validation. No new frames are sent to legacy clients.

For negotiated `scan_finalization_v1`, backend sends `type=scan_status_ack` with session_id, command_id, effective terminal status and has_results **after committing** an owned terminal scan status (including a duplicate of an already terminal command). The receipt reports persisted state, including a different effective terminal result when ingest was definitively closed; it does not assert that a retained artifact was ingested. Agent clears its durable finalization checkpoint only on the matching current-session receipt. Before running it checkpoints the accepted remote scan with finalization protocol 1; after headless writes it checkpoints the saved result before uploading. On restart, replay a saved upload/final status; a definitively closed ingest retains the artifact and reconciles the backend terminal receipt. An interrupted running scan with no saved result reports failed, without rerunning Nmap. The updater refuses a pending checkpoint even when no process holds flock. This closes the existing send-success-versus-DB-commit gap without giving updates scan fields.

An explicit unsupported/404 probe keeps legacy hello/status and the existing scan lifecycle, without creating a protocol-1 checkpoint or claiming durable backend acknowledgement. Transport/server/probe-validation errors retry rather than silently negotiating legacy. A checkpoint already created under protocol 1 survives reconnect and backend downgrade: never clear it on send success, convert it to legacy or discard its artifact. Block new remote scans and updater claims until a compatible session supplies its terminal receipt. Thus old backends continue to support ordinary scans while pending durable work retains its guarantee.

Local socket contract is limited to inspect, check, accept_update and readiness challenge/response. Task 8 adds readiness without enabling accept_update or claiming installation support. Readiness binds a fresh single-use nonce, supervisor-observed systemd invocation, root Unix peer PID equal to MainPID, and app/package versions; verify the invocation/MainPID again before accepting it. Idle startup uses current installed versions, while later operation verification uses its recorded target/invocation. Missing authoritative identity or stale evidence fails readiness. This grants no installation authority, acquires no scan lease and needs no backend connection. During recovery, startup readiness first restores the durable gate, then allows the agent to start and answer this handshake. The external reporter does not wait for WS to preserve local outcome.

Registry replacement and hello persistence share the admission guard. Reject state-changing frames from a replaced capable socket before applying status/hello/update evidence or sending a scan receipt; clear current capability on disconnect. Persist observed version/time only from current accepted hello. Reconciliation combines matching operation/invocation/version hello and updater events in either arrival order. A new socket gets a new session; it may report an already claimed operation but cannot claim/redeliver an old unclaimed request. Direct updater reports are bound to device/org/operation and admitted receipt, not to a surviving old socket.

The guard covers current-socket validation, threadpool DB work and the committed receipt send; all status/progress/hello mutations are fenced before DB work. Take the Agent row only after the guard and keep presence plus the associated mutation in one transaction. No helper may release that row with an intermediate presence commit. Registration/replacement and disconnect persistence also run under the guard; cleanup of a displaced socket must not mark the new socket offline. No DB-row holder waits to acquire the guard.

HTTP report replay is constrained by per-device nonce plus unique `(update_id, sequence)`. Identical duplicates acknowledge; a reused sequence with different content returns 409. Accept only the next sequence, legal transition and immutable release identity; older unseen gaps require replay from the stored acknowledgement. Repeated current-phase evidence is allowed without rerunning side effects. Before claim, only a failed/busy rejection tied to the current unexpired session may finalize a request; all installation evidence requires admitted receipt ownership. A committed event cannot regress a terminal state. Backend hello alone cannot synthesize updater completion. Revocation before claim refuses work; after mutation begins it blocks further remote admission/reporting but cannot safely cancel local recovery. Keep reports locally until restore/authorized reconciliation.

## State, deadlines and closed errors

| From | Evidence / transition | Result |
|---|---|---|
| requested | Companion claims same session before receipt deadline, owns exclusive lock | preparing; operation is admitted exactly once |
| requested | No claim by deadline; delayed frames cannot claim | expired; release reservation, no install |
| preparing | First mutation did not begin before authorization deadline | expired; previous installation unchanged |
| requested/preparing | Device busy, preflight/trust/version failure before mutation | failed; record reason, previous installation unchanged |
| preparing | Artifacts/snapshot verified and start authorization still valid | installing; durable mutation gate precedes side effects |
| installing | Fully configured exact package/environment; process restarted | verifying |
| verifying | Local readiness for target invocation/version succeeds | awaiting_confirmation; commit local outcome and clear local mutation gate |
| awaiting_confirmation | Durable local success plus matching current-session hello | succeeded |
| installing/verifying | Local install or health failure | recovering; one cached previous-version recovery attempt |
| recovering | Prior package/environment configured and locally healthy | rolled_back; durable report records local evidence even if main agent cannot connect |
| recovering / interrupted mutation | Safe targeted repair or local health cannot be proved | needs_intervention; inhibit scans/updates until verified assisted repair |

`failed`, `expired`, `succeeded`, `rolled_back` are terminal. `needs_intervention` retains reservation/gate; an assisted recovery can produce a new sequenced recovering → rolled_back outcome. Disconnect/timeout does not fabricate a local failure. Contact state is a separate projection (`current/stale/unknown`); pending confirmation may remain indefinitely. A backend scan reservation is released only after remote reconciliation; local scans may run once local health is durably committed and the mutation gate is clear.

Proposed initial policy limits, to validate with artificial packages: request claim within 30 s; preparation and first mutation within 20 min of claim; apt-lock wait at most 30 s; local health within 120 s of invocation start. Start-deadline expiry before mutation yields expired; it never authorizes a later reconnect install. Bound network refresh/download calls; no installer progress deadline blindly kills dpkg. After 15 min without local installation progress, mark contact/action overdue and inspect the supervised process; never launch a second package manager. Backend worker expires only unclaimed requests, not admitted installation or confirmation. HTTP reports retry at 5/15/60 s then at most every 5 min, with disk persistence and fresh nonce; 403 pauses delivery pending restore. These are policy proposals, not measured performance or recovery guarantees.

Closed admission HTTP codes: 401 `unauthenticated`; 403 `forbidden` or `device_revoked`; 404 `not_found`; 409 `device_busy`, `version_conflict`, `release_not_allowed`, `idempotency_conflict`, `operation_conflict`, `session_replaced`, `request_expired`; 422 `validation_error`; 503 `device_offline`, `bootstrap_required`, `release_check_unavailable`. Return the existing error envelope, sanitized message and no input echoes. Errors discovered after 202 persist on the same operation; GET still returns its history.

Closed local/update error codes: `device_busy`, `session_replaced`, `request_expired`, `release_not_allowed`, `version_conflict`, `metadata_untrusted`, `metadata_expired`, `artifact_mismatch`, `unsupported_platform`, `prerequisite_missing`, `insufficient_resources`, `package_manager_busy`, `install_failed`, `local_health_failed`, `recovery_failed`, `state_corrupt`. Nullable error_code is not a success signal. Unknown external diagnostics map to install_failed or recovery_failed; keep bounded sanitized evidence locally, never expose shell output or credentials. Backend outage is contact state, not local_health_failed.

## Persistence and concurrency

New tables: `agent_releases` (immutable release identity plus approval/withdrawal metadata), `agent_updates` (org/device/actor, idempotency key + request digest, release/prior/target versions, session, authorization/deadlines, phase, local outcome, observations/times/error), `agent_update_events` (unique ordered sequence, body digest and validated evidence). Store actor ID with nullable-on-delete FK and a safe display snapshot. DB constraints enforce legal phase/code domains, one active update per device, scoped idempotency and event uniqueness; indexes support device history and worker deadlines.

Add nullable version/observed-at/session provenance columns to Agent; no backfill from source version or vanished sockets. Keep online derived. A new singleton `agent_release_catalog_state` table persists trusted catalogue generation/digest/validation times independently of an installation. Migration is additive from the real Alembic head; preserve commands/scans and their existing active index. Downgrade refuses while update records/active reservations would be lost. New models must be registered for Alembic. No migration or schema command runs in this stage.

Both `_claim_agent` for scans and update claim/create lock Agent before checking both lifecycles. Existing scan sweeps cannot expire updates. Registry session checks and DB transactions have the order in ARCHITECTURE.md; a DB error rolls back admission before send. The device lock is the final authority against races with TUI/headless/provisioning. Root maintenance that ignores these contracts remains outside support.

Companion SQLite retains immutable request digest, authorization deadline, before/after package state, snapshot paths, ordered events and backend ack. A crash between backend claim and local receipt causes a same-operation claim lookup, never a new intent; no destructive work before the receipt is durably saved. A crash after install intent inspects actual dpkg/environment/invocation evidence. Unsent outcomes survive main-agent failure. A damaged journal blocks mutation and requests assisted recovery.
